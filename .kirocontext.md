## What this is

**VGC Companion** — a mobile-first, offline-capable **Pokémon Champions VGC (doubles)**
companion PWA for a single competitive ladder player (the developer). Local-first, private,
no accounts, no backend. Build on a PC, publish `dist/` to a free static host once, install
on Android, run fully offline.

**Scope now:** Champions Doubles only. Showdown deferred (seams exist, no adapter).

---

## Non-negotiable domain rules

1. **Champions ≠ Scarlet/Violet.** All EVs maxed. Uses **Stat Points** (0–32/stat) +
   **Stat Alignments** (nature-equivalent). Do NOT apply S/V EV/IV assumptions to
   Champions. Relevant: `src/engine/champions-stat.ts`, `src/stores/team-migration.ts`.
2. **Never present derived/usage data as certainty.** Provenance (source/format/season/
   retrieval time) + computed confidence on every datapoint. Unknown opponent sets are
   probabilities.
3. **Don't claim illegal/unobserved sets.** Matchup features must not assert a move a mon
   isn't observed using.

If a change violates any of these, stop and flag it.

## Tech stack

Vite 8 + React 19 + TypeScript (strict-ish: `verbatimModuleSyntax`, `noUnusedLocals`).
Zustand (state), Dexie/IndexedDB (persistence), React Router v6 (base-path aware).
Tailwind CSS 3 (dark theme). oxlint. Vitest + fake-indexeddb. Custom SW (`public/sw.js`).

---

## Architecture (3 layers)

- **UI** — `src/modules/*` (feature-sliced: `pages/`, `components/`, `hooks/`),
  `src/shared/`, `src/app/` (Layout = bottom-nav, Router = lazy routes).
- **Engine** — `src/engine/*`. **Pure TS, no React.** All math/heuristics. Unit-tested in
  `__tests__/`. Modules share engines (no duplicated logic).
- **Data** — `src/db/*` (Dexie), `src/data/*` (static configs + API adapter in
  `data/sources/`), `src/stores/*` (Zustand, hydrate from IndexedDB).

Routes: `/teams` (⚔️), `/live` (🔴), `/matchup` (🎯), `/lab` (🧪) are primary tabs;
`/meta` (📊), `/guides` (📖), `/data` (⚙️) behind the "More" menu. `/` → `/teams`.

---

## Data source

Champions Battle Data API — `https://championsbattledata.com` (docs `/api_guide`, terms
`/api-rules/`). CORS enabled → browser calls directly. Endpoints: `/api` (index ~237 mons)
and `/api/battle/Doubles/:showdownId` (usage rows, `days=` for snapshots). **No global
per-mon usage %** — popularity is derived from teammate co-occurrence and labeled as such.
**Attribution required and must stay visible in-app.** Adapter: `data/sources/champions-battle-data.ts`.

## Known weak spots (verify / improve — full detail in COPILOT_REVIEW_HANDOFF.md)

1. **`engine/damage-calc.ts`** correctness for Champions (was S/V EV-based) — HIGHEST STAKES.
2. **`data/sources/showdown-mapping.ts`** name reconciliation (forms/regional variants).
3. Stat Points not yet first-class on team members (`evs/ivs` still present).
4. `modules/meta-dashboard/hooks/useMeta.ts` recomputes over all usage — perf.
5. Service worker update/staleness flow.
6. Move Advisor / Matchup Lab heuristic soundness (Protect/redirection/TR).
7. Accessibility (contrast, keyboard, ARIA on custom pickers, focus in slide-up editor).
8. Test coverage beyond pure engines (UI/stores/adapters thin).
9. Error/empty/loading/offline states.
10. Dynamic Tailwind `bg-${type}` classes may be JIT-purged — verify/safelist.

Battle-guides **learning loop** is the intended differentiator and may be underbuilt.

## How to get healthy on a new machine

```bash
npm install
npm run build      # tsc -b && vite build
npm test           # vitest run
npm run lint       # oxlint
npm run dev        # http://localhost:5173
```

Then open the **Data** tab and **Sync usage data** once while online to populate IndexedDB.

Deployment: see `DEPLOY.md` (Netlify Drop is the quick path). Bump `CACHE_VERSION` in
`public/sw.js` on each deploy.
